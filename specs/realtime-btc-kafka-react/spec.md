# cube_test 改造 — 即時 Bitcoin 價格串流（Kafka + React）

Status: CONFIRMED

## Summary

`cube_test` 原本依賴的 Coindesk `v1/bpi/currentprice.json` 已停止服務（實測連線失敗），目前 `/api/bitcoin/price` 永遠回傳寫死的 mock 資料。這次改造要把價格來源換成免費的公開即時來源，用 Kafka 做價格事件串流（即時推播、歷史落地、K 線聚合、價格警示），並加上 React 前端顯示即時價格與圖表。這是一個練習 Java、Kafka 的個人專案，也是之後部署到 K8s、接 GitHub Actions CI/CD 的基礎（CI/CD 另開 spec）。

## Goals

- 用免費、不需 API key 的公開來源取得 **BTC-USD 即時成交價**（逐筆或秒級）
- 其他法幣（TWD、JPY、EUR、GBP…）改用**真實匯率**從 USD 價格換算，取代現在寫死的 `rateRatios`
- 保留幣別管理（幣別代碼 + 中文名稱 CRUD），並由前端提供管理介面
- 價格事件經 Kafka 串流，支援四種用途：
  1. 即時推播到前端
  2. 歷史價格寫進資料庫，可以查詢
  3. 用 Kafka Streams 聚合成 OHLC K 線（至少 1 分鐘、5 分鐘兩種週期）
  4. 價格警示：使用者設定門檻，價格越過門檻時在前端通知
- 新增 React 前端：即時價格、多幣別換算、K 線/走勢圖、幣別管理、警示管理
- 整個系統可以用 docker compose 一鍵在本機啟動（含 Kafka）
- 各個元件符合上 K8s 的前提：已容器化、設定走環境變數、有 liveness/readiness 健康檢查

## Non-Goals

- 不做 K8s manifests / Helm、GitHub Actions CI/CD（另開 spec）
- 不做使用者帳號、登入、權限；系統視為單一使用者
- 不支援 BTC 以外的加密貨幣
- 不做交易、下單、錢包等任何金流功能
- 不做 Email / 推播 / LINE 等站外通知；警示只在前端頁面開著時顯示
- 不保證和舊 API 相容：`/api/bitcoin/price/original`（Coindesk 格式）可以移除，其餘 endpoint 可重新設計
- 不回補歷史資料：歷史與 K 線只從系統開始收資料那一刻起算
- 不做高可用或多 broker 的正式 Kafka 叢集設定（本機單 broker 即可）

## Requirements / User Stories

### 價格來源
1. 系統持續從免費公開來源接收 BTC-USD 即時價格，不需要 API key。
1a. 至少要有一個主要來源和一個備援來源（不同交易所）。主要來源斷線或超過設定秒數沒有新價格時，自動切到備援；主要來源恢復後切回。前端要能看到目前用的是哪個來源。
2. 來源斷線時自動重連；斷線期間前端要能看到「資料延遲 / 已斷線」的狀態，不能靜默顯示舊價格。
3. 匯率從免費公開來源定期更新（頻率 ≥ 每小時一次），用來把 USD 價格換算成其他法幣。
4. 所有外部來源的網址與參數可以用設定（環境變數）切換，不寫死在程式裡。

### 串流與資料
5. 每一筆收到的價格都會成為一個價格事件寫進 Kafka，內容至少包含價格、幣對、來源、事件時間。
6. 價格事件會寫進資料庫；可以依時間範圍查詢歷史價格。
7. 價格事件會用 Kafka Streams 聚合成 1 分鐘與 5 分鐘的 OHLC K 線，K 線可以依時間範圍查詢。
8. 服務重啟後，歷史價格與 K 線不會遺失（需要持久化的資料庫，不能只用 in-memory H2）。
8a. 逐筆歷史價格只保留 30 天，超過的資料自動清除；K 線不受這個限制。

### 前端（React）
9. 作為使用者，我打開頁面就能看到 BTC-USD 即時價格，不用重新整理，價格會自動更新。
10. 作為使用者，我可以看到 BTC 以資料庫中各幣別計價的價格與中文名稱，並知道每個價格用的是哪個時間點的匯率。
11. 作為使用者，我可以切換 1 分鐘 / 5 分鐘 K 線圖，也可以看最近一段時間的價格走勢。
12. 作為使用者，我可以新增、修改、刪除幣別（代碼 + 中文名稱）。
13. 作為使用者，我可以新增、刪除價格警示（例如「BTC-USD 高於 90,000」「低於 80,000」）。
14. 當價格越過警示門檻時，前端會顯示通知。同一個警示觸發後有 5 分鐘冷卻期，冷卻期內不再觸發；冷卻期結束後，條件仍成立就可以再次觸發。
14a. 警示由後端判斷，前端沒開著時也會觸發並記錄。作為使用者，我打開頁面時可以看到上次離開後觸發過、還沒看過的警示。
14b. 系統第一次啟動時預先建立幣別資料：USD 美元、EUR 歐元、GBP 英鎊、TWD 新台幣、JPY 日圓。

### 維運與品質
15. 每個後端元件都有 liveness / readiness 健康檢查，Kafka 或資料庫連不上時 readiness 要回報失敗。
16. 設定（資料庫、Kafka 位址、外部來源網址等）全部可以用環境變數覆寫。
17. 同一份 Dockerfile 可以建出 amd64 與 arm64 的 image，取代現在的 `Dockerfile.amd64` / `Dockerfile.silicon`。
18. 自動化測試不依賴真實外部價格來源，也不依賴開發者本機已經啟動的 Kafka。
19. 從 repo 移除已 commit 的 `target/` 等建置產物，並加入 `.gitignore`。

## Acceptance Criteria

- [ ] 在乾淨環境執行 `docker compose up`，全部服務啟動後，不需要任何 API key，打開前端 30 秒內可以看到持續跳動的 BTC-USD 價格
- [ ] 手動切斷對外價格來源的網路，前端在 30 秒內顯示斷線/延遲狀態；恢復網路後自動恢復更新，不用重啟服務
- [ ] 前端的幣別換算價格和匯率來源的匯率相比，誤差 < 0.5%，並顯示匯率更新時間
- [ ] 系統持續跑 10 分鐘以上後，可以查到該時段的歷史價格，以及至少 10 根 1 分鐘 K 線與 2 根 5 分鐘 K 線；每根 K 線的 open/high/low/close 和同時段的歷史逐筆價格一致
- [ ] 重啟後端服務與資料庫後，先前的歷史價格與 K 線仍然查得到
- [ ] 主要價格來源被封鎖（例如用設定指到錯誤網址或擋掉網路）時，30 秒內自動切換到備援來源，前端顯示目前來源；主要來源恢復後切回
- [ ] 在前端新增一個門檻設在目前價格附近的警示，價格越過門檻時畫面出現通知；5 分鐘內不會再通知同一個警示，5 分鐘後條件仍成立會再通知一次
- [ ] 關掉前端後觸發的警示，重新打開頁面時會顯示為「未讀」
- [ ] 超過 30 天的逐筆價格會被自動清除（測試可用縮短的保留期驗證）；K 線不受影響
- [ ] 全新資料庫啟動後，幣別清單已經有 USD/EUR/GBP/TWD/JPY 與中文名稱
- [ ] 前端可以完成幣別的新增、修改、刪除，重新整理後結果仍在
- [ ] 停掉 Kafka 後，後端的 readiness 回報失敗；Kafka 恢復後 readiness 自動恢復
- [ ] `mvn verify`（以及前端的測試指令）在沒有網路連外、沒有預先啟動 Kafka 的環境下全部通過
- [ ] `docker buildx build --platform linux/amd64,linux/arm64` 可以成功建出後端 image
- [ ] repo 裡沒有 `target/`、`node_modules/` 等建置產物

## Constraints & Assumptions

- 技術棧：後端用 Java 21（從目前的 17 升級）+ Spring Boot（目前 3.2.3，版本升級由 plan 決定）、Maven；前端使用 React；串流使用 Apache Kafka 與 Kafka Streams。以上是使用者指定的學習目標，不是可以替換的選項
- 已確認（2026-09-29 實測）可用、免 API key 的價格來源：Coinbase、Binance、Kraken（有即時 WebSocket）、CoinGecko（REST，有多幣別）。實際選用哪一個留給 plan 決定
- Binance 對美國 IP 有地區限制，而 GitHub Actions 的 runner 多半在美國；這也是需求 18（測試不依賴真實外部來源）存在的原因之一
- 免費來源有 rate limit 與服務條款限制；本專案只做個人學習用途，不對外提供價格資料服務
- 假設使用者在台灣、用 Apple Silicon Mac 開發，本機資源足以同時跑 Kafka、資料庫、後端、前端
- 前端介面語言為繁體中文
- 系統是單一使用者、沒有登入，因此不處理警示或幣別資料的權限隔離
- 本 spec 完成的狀態必須能讓下一份「K8s + CI/CD」spec 直接接手，不需要再改應用程式的設定方式

## Decisions（2026-09-29 使用者確認）

- 即時價格來源：主要來源與備援來源都要做；選哪兩家由 plan 階段依「哪個最好實作」決定
- 匯率來源：由 plan 階段依「哪個最好實作」決定
- 逐筆歷史價格保留 30 天
- 警示觸發後冷卻 5 分鐘，之後條件成立可再次觸發
- 前端沒開著時觸發的警示，下次打開要顯示
- Java 升級到 21
- 預先建立 USD/EUR/GBP/TWD/JPY 幣別資料
